# Git 쓰기 정책

`git_write`는 실행자가 실행 준비 화면에서 선택하며 기본값은 `deny`다.

| 값      | 허용 범위                                                          |
| ------- | ------------------------------------------------------------------ |
| `deny`  | Git 쓰기 금지                                                      |
| `local` | add·commit, 브랜치 생성/전환/삭제, 태그, merge/rebase 등 로컬 변경 |
| `push`  | local 범위와 원격 push·`gh pr create`                              |

셸 읽기 전용/금지 또는 저장소 편집 금지는 Git 쓰기에도 우선한다. `push`를
선택해도 네트워크·자격증명 차단을 풀지 않으므로, 기존 SSH/CLI 인증 환경과
네트워크 정책에 따라 전송이 실패할 수 있다. 자격증명을 읽거나 sandbox를
우회하라는 의미가 아니다.

`push`는 capability와 관계없이 `git_remote_write` 항목을 기존 위험 확인
모달에서 개별 승인해야 한다. 서버가 정확한 승인 집합을 확인하고 정책과 승인
키를 실행 명령·감사 기록에 남긴다. 데몬은 같은 공통 함수로 독립 검증한다.
원격 기록·CI·알림은 되돌릴 수 없다는 위험을 고지하며, 이 항목은 부족한
capability가 아닌 명시적 허용에 따른 위험이다.

Claude hook은 Git 명령 패턴을 단계별로 적용한다. Git 단계 또는 셸/저장소
제한에 걸린 Git 작업은 실행 중 `ask`로 예외 승인하지 않는다. 그렇게 허용하면
실행 전 원격 위험 승인을 우회할 수 있기 때문이다. 명령 hook이 없는 provider는
`deny/local`을 강제할 수 없으므로 별도 `git_write` 위험 확인을 요구한다.

정규식은 셸 파서나 Git 자체의 접근 제어가 아니다. 옵션·인용·복합 명령의
일반적인 형태를 검사하지만, 임의의 스크립트·기존 Git alias가 숨긴 동작까지
증명하지 않는다. 인자에 포함된 명령 이름을 보수적으로 차단할 수도 있다.
`branch/tag`의 조회 형태도 `deny`에서는 함께 차단하고 `status/diff/log/show`는
허용한다. 모든 provider의 시스템 규약은 선택한 단계와 같은 문구를 사용한다.
